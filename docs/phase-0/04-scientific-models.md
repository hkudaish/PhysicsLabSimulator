# Scientific engine specification, draft model versions 0.1

These are design contracts and proposed acceptance cases. No solver is implemented or scientifically certified in Phase 0.

## Chemistry: dilution-v1

Curated nonreactive, fully dissolved single-solute aqueous solution at fixed temperature and pressure; ideal additive volumes. No precipitation, evaporation, volume contraction, heat production or pH prediction. Outside this domain return `UnsupportedModel`, not a guessed result. No real chemical safety advice is generated by this model.

Entities: Substance (ID, formula, reviewed molar mass and source/version); Solution (solute ID, amount mol, solvent volume L, total volume L); Vessel (ID, capacity L, contents); Transfer (source, destination, volume L); Observation (quantity, value, unit, model version, revision). Future reactions separately define balanced coefficients, supported temperature/pressure, limiting reagent, products and enthalpy; only validated reaction packs may run.

Canonical units: mol, L, mol/L, K. UI converts mL to L before commands. `n = C × V`; well-mixed transfer `n_transfer = n_source × V_transfer / V_source`. Subtract exactly those amounts from source, add to destination. Adding pure water changes volume and preserves solute amount: `C_final = n_total / V_total`. `C1 V1 = C2 V2` applies only to the described dilution assumptions. Empty vessel concentration is undefined, not NaN displayed as a reading.

Reject negative/nonfinite values, nonpositive final volumes, transfers larger than available volume, incompatible solutes, and capacity overflow. Zero-volume transfer is a valid no-op. Temperature changes, unsupported mixtures and reactive solutes return `UnsupportedModel`. A rejected command does not mutate either vessel. Solver uses double precision; compare reference concentrations with absolute tolerance 1e-10 mol/L plus relative 1e-9, quantities with absolute 1e-12 mol or L plus relative 1e-9. These are computational tolerances; a teaching instrument's display resolution (proposed 1 mL, 0.001 mol/L) is separate and needs reviewer approval.

## Electricity: resistive-dc-v1

Static ideal DC sources, positive linear resistors, ideal wires and switches only. Graph contains component IDs, typed terminals, connections, a reference node, resistance ohm, voltage V and rated power W. Wires merge nodes before solving. Phase 1 UI constrains values to proposed 0–12 V and 10–10,000 ohm; faults such as a zero-ohm source bypass remain possible through wiring. Bounds require scientific approval. LEDs, capacitors, AC, semiconductor behavior and thermal burnout dynamics belong to later reviewed models.

For each resistor `g=1/R`, stamp +g on diagonal node entries and -g on off-diagonals. Add one unknown current per independent ideal voltage source and its incidence constraint. Solve `[G B; Bᵀ 0][v; i_source] = [j; e]` with pivoting. Chosen ground removes the reference unknown. Compute resistor current `(v_a-v_b)/R`, power `I²R`, and verify KCL residuals after solving. Current sign follows the declared a→b terminal order. Do not use a single equivalent resistance formula for arbitrary assembled graphs.

Return `Solved`, `OpenCircuit`, `FloatingNetwork`, `ShortCircuit`, `InconsistentSources`, `InvalidInput` or `NumericallySingular`. Detect ideal-source bypass and contradictory ideal sources before numerical division. A disconnected resistor carries 0 A, but an unreferenced floating terminal has no valid absolute voltage. Display unavailable voltage as “—”, not zero. A short circuit has no finite ideal-source current; show a fault and inhibit current reading, never infinity or arbitrary clipping. Exceeded power rating produces an overload warning in Phase 1; do not simulate a timed burnout without an approved thermal model.

Voltmeter: ideal infinite impedance across two valid nodes; ammeter: insert an ideal zero-voltage branch, detect invalid across-source placement as a fault. Unit selection and connection mode are explicit. Solver target error: abs 1e-9 A or V + rel 1e-8; scaled linear-system residual <=1e-9. Display precision does not alter solver inputs.

Series/parallel reference cases verify solver generality in Phase 1; dedicated lessons and broad component UI remain Phase 2.

## Integration and validation

`command(expectedRevision, modelVersion) → validate → solve → atomic state/event commit → renderer/measurement refresh`. Include command/event IDs, state revision, schema/model/experiment versions and canonical units. Undo applies a prior valid snapshot and journals the action; reset starts a new revision without silently overwriting a saved attempt. Threaded calculations return data only; Unity object access remains on the main thread. Stale asynchronous results must be discarded by revision.

Fixtures in `specs/science/reference-cases.json` are independent analytical expectations for future C# tests. Phase 0 checks fixture consistency, not solver accuracy. Phase 1 must implement all cases including invalid states, conservation, graph topology, serialization and rendering-independent results, then obtain scientific reviewer signoff with equation references and dataset licenses. No dataset or reviewer is yet approved. Model/version changes cannot reinterpret existing published attempts silently.
